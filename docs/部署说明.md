# 识典古籍重建平台 · 服务器部署说明

> 目标机器：华为云 `60.204.248.157`（ZBCX 应用工厂标准环境）
> 部署形态：**形态 A（同进程多模块）** —— 挂进既有 `zbcx-web` 服务，不新建进程、不动既有模块。

## 一、部署拓扑

```
浏览器 ──https──> nginx(:8081)
                    ├─ /guji/       静态站点  /www/wwwroot/guji（uni-app H5 产物）
                    └─ /guji-api/   反代 ──> 127.0.0.1:9099（RuoYi-FastAPI）
                                              ├─ /api/ancientlib/**  新增古籍模块（218 条路由）
                                              └─ /guji/**            既有旧模块（7 条路由，未改动）
后端 ──> PostgreSQL zbcx_sj（244 本古籍 / 15039 章 / 691241 段）
```

## 二、目录与文件落位

| 用途 | 路径 |
|---|---|
| 后端工程 | `/root/zbcx/RuoYi-FastAPI/ruoyi-fastapi-backend` |
| 古籍模块 | `.../ruoyi-fastapi-backend/module_guji` |
| 数据迁移 SQL | `module_guji/scripts/migrate_real_data.sql` |
| 数据打磨 SQL | `module_guji/scripts/polish_data.sql` |
| 名句种子 SQL | `module_guji/scripts/seed_quotations.sql` |
| 前端站点 | `/www/wwwroot/guji` |
| nginx 配置 | `/www/server/nginx/conf/panel_proxy.conf`（追加 `/guji/`、`/guji-api/`） |
| 服务单元 | `/etc/systemd/system/zbcx-web.service` |

## 三、部署步骤

### 1. 备份（必做）

```bash
TS=$(date +%Y%m%d-%H%M%S)
mkdir -p /root/zbcx/backup/$TS-guji-old
cp -a /root/zbcx/RuoYi-FastAPI/ruoyi-fastapi-backend/module_guji/. /root/zbcx/backup/$TS-guji-old/
cp -a /www/server/nginx/conf/panel_proxy.conf /www/server/nginx/conf/panel_proxy.conf.bak-$TS-guji
```

### 2. 上传后端模块（加法合并）

本机打包后单包上传，**避免多文件逐个 PUT 丢文件**（实测会丢）：

```bash
tar --exclude='__pycache__' --exclude='entity/vo/guji_vo.py' -czf module_guji.tar.gz module_guji
# 上传后在服务器同一会话内解压并校验
tar xzf module_guji.tar.gz
```

> `entity/vo/guji_vo.py` 与既有旧模块同名但内容不同，**必须排除**，否则旧模块会崩。

### 3. 建表 + 迁移真实数据

```bash
cd /root/zbcx/RuoYi-FastAPI/ruoyi-fastapi-backend
./venv/bin/python -m module_guji.scripts.migrate_real_data   # 建 guji_* 表

export PGPASSWORD='<密码>'
/www/server/pgsql/bin/psql -U zbcx -d zbcx_sj -h 127.0.0.1 -v ON_ERROR_STOP=1 \
  -f module_guji/scripts/migrate_real_data.sql              # 迁移 gj_* → guji_*
/www/server/pgsql/bin/psql -U zbcx -d zbcx_sj -h 127.0.0.1 -v ON_ERROR_STOP=1 \
  -f module_guji/scripts/seed_quotations.sql                # 名句（真书真句对比入库）
/www/server/pgsql/bin/psql -U zbcx -d zbcx_sj -h 127.0.0.1 -v ON_ERROR_STOP=1 \
  -f module_guji/scripts/polish_data.sql                    # 章节重拆 + 简介清洗
```

迁移结果：

| 表 | 行数 |
|---|---|
| guji_book | 244 |
| guji_category | 5（经/史/子/集/其他） |
| guji_chapter | 15039（打磨前 4339） |
| guji_paragraph | 691241 |
| guji_quotation | 51 |
| guji_recommend | 12 |

### 4. 重启后端

```bash
systemctl restart zbcx-web
systemctl is-active zbcx-web        # 应为 active
curl -s http://127.0.0.1:9099/api/ancientlib/read/book/count
```

### 5. 构建并部署前端

```bash
cd guji-uniapp
npm install --registry=https://registry.npmmirror.com
VITE_GUJI_BASE_URL=/guji-api npm run build:h5     # API 走 nginx 前缀，同源无跨域
tar czf h5.tar.gz -C dist/build/h5 .
# 上传后：先删后拷（保留 uploads），勿用覆盖式解压
cd /www/wwwroot/guji && rm -rf assets static index.html && tar xzf h5.tar.gz -C /www/wwwroot/guji
```

### 6. nginx 配置（追加）

```nginx
location ^~ /guji/ {
    alias /www/wwwroot/guji/;
    index index.html;
    try_files $uri $uri/ /guji/index.html;
}
location ^~ /guji-api/ {
    proxy_pass http://127.0.0.1:9099/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

```bash
nginx -t && nginx -s reload
```

## 五、踩坑记录

| 问题 | 原因 | 解决 |
|---|---|---|
| 多文件逐个 SFTP PUT 丢文件 | 远程写盘异常 | 改 tar 单包上传 + 同会话内解压校验 |
| SQLAlchemy 执行迁移脚本报多语句错误 | 不接受 `;` 分隔脚本 | 改用 psql 直接执行 `.sql` |
| 数据打磨跑 10 分钟未完成被超时杀掉 | 关联子查询逐行扫描 69 万段 | 改「临时索引 + 区间连接」，3 分钟内完成 |
| 124 本书只有 1 个「全篇」章节 | 源数据未按篇拆分 | 按短行标题规则重拆，单章书降至 5 本 |
| 首页搜索「论语」无结果 | 前端需回车触发（非缺陷） | 已确认后端返回正常 |
